# 项目一致性、Redis 与运维整改

用户已授权修复项目审查中列出的全部问题，并增加 Redis 限流与幂等。

## 规则
- URL 中分组、项目参数接受 UUID，也兼容旧 slug。新生成链接使用 UUID，避免跨所有者重名。旧 slug 歧义仍拒绝访问，不能任意选取。
- owner 执行管理写操作；member 按七项模块读取权限访问。告警确认是明确例外：issues:read 允许查看及确认，不能编辑规则。
- connected 表示曾成功连接；active/stale 表示最近 24 小时是否有接入活动，disabled 表示该采集模块关闭；界面明确命名，不混用。
- Redis 提供跨实例原子窗口限流，SDK、邀请、认证分别命名空间。认证按 IP 和归一化账号双维度限流，键不保存明文凭据。生产启用 Redis，服务异常返回 503，不绕过限制；本地未配置 Redis 可使用有界内存实现。
- 管理写请求支持 Idempotency-Key：按用户、方法和 URL 隔离；同 key 不同负载返回 409，并发进行中返回 409，成功结果短期重放。Redis 仅用于请求协调，数据库唯一约束、事务和 SDK 载荷校验继续承担持久一致性；认证响应不缓存。
- 重置密码增加会话版本，旧 JWT 即失效。
- 邀请邮件在持久化待发送任务后由后台事务外投递，避免持锁等待 SMTP。投递失败可重发，旧链接失效，任务中令牌加密且完成后清除；发送失败/超时可重试，邮件按至少一次投递设计。
- 清理提供 dry-run、显式执行入口和可配置定时执行；监控数据默认 30 天，审计按独立保留策略处理，不能删除仍需引用的错误事件而破坏 issue。
- 数据库索引匹配告警窗口与总览事件时间查询；接入状态按数据类型批量聚合，避免每项目每信号一次查询。

## 验证
新增行为先编写回归测试；运行前后端完整测试、构建、类型检查及变更文件静态检查。真实 Redis 集成测试使用独立前缀并清理；PostgreSQL 迁移和事务测试仅在显式测试连接下执行。不同实例同时请求、载荷冲突、依赖不可用及权限撤销是重点边界。不得重置、覆盖用户已有改动，不自动提交或发布。
